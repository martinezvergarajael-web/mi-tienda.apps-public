Servicios y notificaciones

Servicios, tareas en segundo plano, notificaciones, proveedores de contenido y la nube para apps móviles.

5.1 Definición

Un servicio es un componente de la aplicación que realiza trabajo sin interfaz de usuario, normalmente de larga duración o que debe continuar aunque el usuario cambie de pantalla. Una notificación es un mensaje que la app muestra fuera de su interfaz (barra de estado, pantalla de bloqueo) para informar o invitar a una acción.

5.2 Tareas en segundo plano

Son operaciones que se ejecutan sin bloquear el hilo principal (UI) y, en ocasiones, sin que la app esté visible: sincronizar datos, descargar archivos, subir fotos, reproducir música o enviar registros. Android limita el trabajo en segundo plano para cuidar la batería, por lo que se debe elegir la herramienta adecuada:

HerramientaCuándo usarla
Corrutinas / hilosTrabajo corto mientras la app está abierta (red, BD)
WorkManagerTrabajo diferible y garantizado (sincronizar, subir logs), aunque se cierre la app
Foreground ServiceTarea visible para el usuario (música, navegación, descarga) con notificación persistente
AlarmManagerAcciones a una hora exacta (alarmas, recordatorios)
Servicio enlazado (Bound)Comunicación cliente-servidor entre componentes

5.3 Tratamiento de notificaciones

Tipos

  • Locales: las genera la propia app (recordatorios).
  • Push (remotas): llegan desde un servidor mediante Firebase Cloud Messaging (FCM) o APNs en iOS.

Elementos

  • Canal (NotificationChannel, Android 8+)
  • Ícono, título y texto
  • Acciones y PendingIntent
  • Prioridad/importancia

Permiso

Desde Android 13 se necesita el permiso POST_NOTIFICATIONS solicitado en tiempo de ejecución.

5.4 Proceso de implementación

A) Proveedores de contenido (Content Providers)

Permiten compartir datos de forma controlada entre aplicaciones (contactos, calendario, galería) mediante URIs y un ContentResolver.

  1. Crear una clase que extienda ContentProvider e implementar query, insert, update, delete, getType.
  2. Definir la authority y las URIs (content://com.ejemplo.app.provider/tareas).
  3. Declararlo en el AndroidManifest.xml con permisos.
  4. Consumirlo con contentResolver.
<provider
    android:name=".TareasProvider"
    android:authorities="com.ejemplo.app.provider"
    android:exported="false" />

// Consumir contactos del sistema
val cursor = contentResolver.query(
    ContactsContract.Contacts.CONTENT_URI, null, null, null, null)

B) Tareas en segundo plano con WorkManager

  1. Agregar la dependencia androidx.work:work-runtime-ktx.
  2. Crear una clase Worker con el trabajo en doWork().
  3. Definir restricciones (red, batería) y encolar la solicitud.
class SyncWorker(ctx: Context, p: WorkerParameters) : Worker(ctx, p) {
    override fun doWork(): Result {
        // sincronizar datos con el servidor
        return Result.success()
    }
}

val restricciones = Constraints.Builder()
    .setRequiredNetworkType(NetworkType.CONNECTED).build()
val peticion = PeriodicWorkRequestBuilder<SyncWorker>(15, TimeUnit.MINUTES)
    .setConstraints(restricciones).build()
WorkManager.getInstance(this).enqueue(peticion)

C) Notificaciones

  1. Pedir el permiso POST_NOTIFICATIONS (Android 13+).
  2. Crear el canal de notificación.
  3. Construir la notificación con NotificationCompat.Builder.
  4. Mostrarla con NotificationManagerCompat.notify().
val canal = NotificationChannel("avisos", "Avisos", NotificationManager.IMPORTANCE_DEFAULT)
getSystemService(NotificationManager::class.java).createNotificationChannel(canal)

val intent = PendingIntent.getActivity(this, 0, Intent(this, MainActivity::class.java),
    PendingIntent.FLAG_IMMUTABLE)

val noti = NotificationCompat.Builder(this, "avisos")
    .setSmallIcon(R.drawable.ic_notificacion)
    .setContentTitle("Recordatorio")
    .setContentText("Tienes una tarea pendiente")
    .setContentIntent(intent)
    .setAutoCancel(true)
    .build()

NotificationManagerCompat.from(this).notify(1, noti)

D) Servicio en primer plano (resumen)

class MusicaService : Service() {
    override fun onStartCommand(i: Intent?, f: Int, id: Int): Int {
        val noti = NotificationCompat.Builder(this, "musica")
            .setSmallIcon(R.drawable.ic_musica).setContentTitle("Reproduciendo").build()
        startForeground(1, noti)   // obligatorio mostrar notificación
        return START_STICKY
    }
    override fun onBind(i: Intent?): IBinder? = null
}

5.5 Servicios de cómputo en la nube para apps móviles

ServicioPara qué sirve
Firebase (Auth, Firestore, Realtime DB, Storage, FCM, Crashlytics, Analytics)Backend completo sin servidor: usuarios, datos en tiempo real, archivos, notificaciones push y reportes de errores
AWS Amplify / Lambda / S3 / CognitoAutenticación, funciones sin servidor, almacenamiento y APIs
Google Cloud (Cloud Functions, Cloud Run)Lógica de backend escalable
Microsoft Azure Mobile Apps / App CenterBackend móvil, distribución y análisis
SupabaseAlternativa open source (PostgreSQL, Auth, Storage)

Modelos de servicio: IaaS (infraestructura), PaaS (plataforma) y BaaS (Backend as a Service, como Firebase) — este último es el más usado en apps móviles porque evita administrar servidores.
